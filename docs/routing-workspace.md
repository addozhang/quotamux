# Routing workspace 0.2.0

## Product contract
Routing is the application workspace and its default screen. A model rail selects one public model. Its main panel contains the model identity and protocols, editable layer cards with target selectors, time windows, current effective order and live target health/capacity. Editing happens on those same cards. Accounts opens an in-workspace drawer for backend credentials, upstream models and shared capacity pools. Statistics and request history are scoped to the selected public model. All is a global rail entry with Statistics and History only. Global account totals and alerts belong to All. Model-filtered history is filtered on the server before cursor pagination. Scope changes clear child rows and pagination; stale responses cannot replace another scope. The original dark visual language defines colors, typography, density and controls. Enable edit is a local one-click toggle; read-only mode disables all configuration mutations while navigation remains available. One global Save button validates and commits the draft; successful save immediately affects new requests. Discard reloads the active document. Polling updates live state without replacing dirty inputs. Conflict and validation failures retain the draft. Secret fields stay blank after loading; blank preserves an existing key by backend/credential identity.

## Single ownership and runtime publication
The configuration document is the routing graph. The same document creates the executing immutable request snapshot and the editable workspace representation. A process-wide Workspace owns the active revision and serialized save transactions. Each HTTP request captures one executing snapshot; an ongoing stream and its fallback retain that snapshot. Runtime circuits are reused only for unchanged target execution identities; changed credentials/endpoints/models receive isolated circuits. Statistics retain their existing store and original layer identity.

Readable TOML is the durable configuration. redb remains the request/statistics ledger. Candidates undergo structural/reference validation, client construction and real upstream checks of new or changed credential/model bindings before persistence. Listener and data-directory changes are rejected by this live editor. Other supported settings activate with the routing snapshot. File-write failures leave the current snapshot active. A successful transaction publishes the already constructed runtime immediately; there is no pending apply state. Concurrent writers provide their base revision; stale writes return conflict. The local editor is enabled with one click. Browser writes must originate from the same origin.

## Published usage prices
Each upstream model can declare default USD-per-million usage rates, optional pricing_schedule with one IANA timezone and non-overlapping weekly price windows, plus pricing_note and pricing_source for billing context. Price windows contain name, days, start, end and the three rate fields. Upstream attempts capture the applicable price at their own start; streams keep that captured price through completion and concurrent saves. Historical estimates are persisted and never repriced on configuration changes. Public model route priority schedules and provider price schedules are separate properties of the same routing document. Subscription allowance value must be labeled as such; unpublished currency token prices remain absent, with the published billing rules stated in notes.

## Time policy
Each public model has timezone (default UTC), default layers in stored order, and zero or more schedules. A schedule has unique name, days (ISO Monday=1 through Sunday=7), start/end local HH:MM or HH:MM:SS, and order containing every layer name exactly once. Start is inclusive, end exclusive. Overnight windows belong to their start weekday. Equal start/end and overlapping weekly windows are invalid. One calendar evaluator serves execution, current display, and a read-only future-time preview. Evaluation happens once at request admission. UTC instants converted to IANA local time govern DST: skipped wall times do not occur and repeated times match both occurrences.

## Capacity policy
capacity_pools is a list of {id,max_in_flight}; each credential optionally references pool. Omission explicitly means no local limit. Multiple keys/models may share one pool. A process-wide counter registry survives every save and keeps outstanding leases across removal/re-addition. Occupancy is attached to stable account/credential identities; assigning or renaming a pool immediately includes existing requests, including formerly unlimited requests. Pool limits may shrink below occupancy, preventing further admission until occupancy falls below the new limit. Nonblocking acquisition precedes circuit admission. A full target is skipped immediately, then remaining targets of its layer, then lower layers. Local capacity skips never trip provider circuits. The lease lasts through same-target retries and the complete upstream stream, and is released on cancellation, failure or completion. Exhausted local capacity returns a retryable 503 rather than an unbounded queue. An independent concurrent save cannot reset occupied counters.

## API contract
GET /api/routing returns {revision,document,models,pools,pricing,now}. document is Config JSON with every api_key replaced by an empty string. Endpoints containing credentials, a query or a fragment are returned as null; leaving the endpoint blank preserves the existing endpoint for the same backend and adapter. models runtime rows contain name, aliases, active_schedule (null for default), effective_order (layer names), and layers [{index,name,strategy,targets:[{backend,credential,upstream_model,circuit,pool,in_flight,max_in_flight}]}]. pools holds live {id,in_flight,max_in_flight}. now is an RFC3339 timestamp. GET accepts ?at=RFC3339 for preview of committed routing and price rules without changing runtime. pricing contains backend/model identities, active_window and selected rates. PUT /api/routing accepts {revision,document}, and returns the same workspace shape on success. Errors return {error}; 409 means stale revision or temporary validation capacity, 422 invalid candidate, 503 persistence unavailable. Existing /api/routing/stats, /api/stats, /api/requests and /api/status serve the captured active runtime.

Config uses version 4 and adds top-level capacity_pools: [{id,max_in_flight}], credentials[].pool: optional string, models[].timezone: string (UTC default), models[].schedules: [{name,days,start,end,order}]. Version 3 configuration automatically upgrades in memory, then persists after constructing a valid runtime. A private original-file backup supports operational downgrade. Read-only directories retain a working in-memory migration and an actionable workspace notice. Model names, aliases, order, prices, protocols, keys, startup settings and historical ledger records are preserved; no schedules or local limits are invented. Repeated startup is idempotent. `--check` never writes the file. Backends retain existing adapter, endpoint, credentials, models and pricing fields. Model layer targets retain backend/credential/model references.

## Acceptance gates
1. Fresh automated regression suite and schema/serialization checks.
2. Schedule exact boundaries, overnight/week wrap, timezone/DST, overlap rejection, default restoration and preview/execution parity.
3. Live HTTP fallback under occupied pools, shared-account cross-model limits, same-layer alternatives, lower-layer fallback, all-busy response, stream cancellation release, shrinking limits, save while requests remain active, credential/circuit isolation.
4. Real browser E2E on isolated 8081: initial unified workspace; model/layer/target editing; accounts/pools; time-window creation and preview; save immediate inference effect; dirty draft protection; invalid key rejection without persisted change; stale writer; responsive layout; statistics and history child views.
5. Real elapsed-time transitions through default, window A, window B and default without edits or restart. Fresh paid Ollama and existing provider smoke on 8081, preserving protocol behavior.
6. Promote the exact tested image to 8080 with restart unless-stopped and the production ledger; verify live configuration, schedule, health, UI and smoke. Production is never the development or E2E target.

## Implementation sequence
