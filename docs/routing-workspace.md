# Routing workspace 0.2.0

## Product contract
The initial screen is All Statistics with a 1 day range. Selecting All or a public model opens Statistics and resets the range to 1 day and the metric to Calls. All offers Statistics and History; a model also offers Routing. Statistics and history stay scoped to the selected public model. All and model statistics offer 1 hour, 1 day, 1 week, 1 month and All time. Finite ranges are rolling intervals ending at the last completed minute. Model-filtered history is filtered on the server before cursor pagination. Scope changes clear child rows and pagination; stale responses cannot replace another scope, Accounts or Settings. Configuration adoption preserves model selection by name across reorder and reloads its visible child data.

Accounts is a separate full-width page reached through the header, with one tab per account. Only the selected account is rendered. Each account contains its credentials, assigned shared capacity pools, upstream models/protocols, billing context, default/current rates and weekly price windows. Capacity cards show the live occupancy, configured maximum and all account/credential references sharing that pool. Creating a pool from a credential explicitly assigns that credential; existing pools remain selectable by other credentials. Pool renames preserve all bindings. Confirmed pool deletion clears its bindings and explains that affected credentials become locally unlimited; changes remain draft-only until Save.

Account deletion is available beside the selected account heading while editing. Before showing deletion confirmation, the browser checks every routing target in every draft model and layer, including inactive and fallback layers. A referenced account remains in the draft and the notice lists its dependent model/layer locations. Dependencies must be removed or reassigned before deletion. Unused accounts require deletion confirmation and then the normal confirmed Save. The server independently rejects dangling account references before publication or persistence; concurrent edits remain protected by revision checks. Historical statistics do not create configuration dependencies and remain intact after deleting an unused account.

Settings is an independent header page for global runtime parameters, including request size, timeouts and affinity tuning. Listener and data location are informational because they require a restart. Read-only Accounts and Settings use labeled information without editable controls or mutation buttons. Enable edit reveals their existing fields. New accounts select their tab, deleted accounts select a valid neighbor, and save/reload preserves the selected account by identity. Navigation retains the shared draft. Workspace returns to the selected model or All. Workspace, Accounts and Settings share one draft, one edit toggle and one confirmed Save transaction. The original dark visual language defines colors, typography, density and controls.

Enable edit is a local one-click toggle. Read-only Routing shows the selected model heading and Live priority; Add model and the save footer are hidden. While editing, the model page contains identity/protocols, layer and target editors, priority time windows, live health/capacity and saved-policy preview. Each deletion identifies its object and requires confirmation before changing the draft. Removing published rates confirms removal of its price windows too. All updates, including field edits and priority moves, require confirmation at Save before any write request. Save validates the complete draft and immediately applies it to new requests. Cancellation preserves the draft and active configuration. Discard and disabling editing require confirmation when a draft is dirty. Polling updates live state without replacing dirty inputs. Conflict and validation failures retain the draft. Secret fields stay blank after loading; blank preserves an existing key by backend/credential identity.

Model statistics show a No final target row only when requests lack a recorded final layer or target. These remain part of that model's total, including requests that could not select a target and compatible historical records lacking attribution. Active alerts contain account and credential identities, not a public-model identity; they belong to All and show current state independently of the selected statistics interval. Saved price previews include only the selected model's upstreams.

GLM Coding Plan is the product label for the existing `zhipu-coding-plan` configuration identity. Saved identifiers and historical attribution remain unchanged.

## Single ownership and runtime publication
The configuration document is the routing graph. The same document creates the executing immutable request snapshot and the editable workspace representation. A process-wide Workspace owns the active revision and serialized save transactions. Each HTTP request captures one executing snapshot; an ongoing stream and its fallback retain that snapshot. Runtime circuits are reused only for unchanged target execution identities; changed credentials/endpoints/models receive isolated circuits. Statistics retain their existing store and original layer identity.

Readable TOML is the durable configuration. redb remains the request/statistics ledger. Candidates undergo structural/reference validation, client construction and real upstream checks of new or changed credential/model bindings before persistence. Listener and data-directory changes are rejected by this live editor. Other supported settings activate with the routing snapshot. File-write failures leave the current snapshot active. A successful transaction publishes the already constructed runtime immediately; there is no pending apply state. Concurrent writers provide their base revision; stale writes return conflict. The local editor is enabled with one click. Browser writes must originate from the same origin.

## Published usage prices
Each upstream model can declare default USD-per-million usage rates, optional pricing_schedule with one IANA timezone and non-overlapping weekly price windows, plus pricing_note and pricing_source for billing context. Price windows contain name, days, start, end and the three rate fields. Upstream attempts capture the applicable price at their own start; streams keep that captured price through completion and concurrent saves. Historical estimates are persisted and never repriced on configuration changes. Public model route priority schedules and provider price schedules are separate properties of the same routing document. Subscription allowance value must be labeled as such; unpublished currency token prices remain absent, with the published billing rules stated in notes.

## Time policy
Each public model has timezone (default UTC), default layers in stored order, and zero or more schedules. A schedule has unique name, days (ISO Monday=1 through Sunday=7), start/end local HH:MM or HH:MM:SS, and order containing every layer name exactly once. Start is inclusive, end exclusive. Overnight windows belong to their start weekday. Equal start/end and overlapping weekly windows are invalid. One calendar evaluator serves execution, current display, and a read-only future-time preview. Evaluation happens once at request admission. UTC instants converted to IANA local time govern DST: skipped wall times do not occur and repeated times match both occurrences.

## Capacity policy
capacity_pools is a list of {id,max_in_flight}; each credential optionally references pool. Omission explicitly means no local limit. Multiple keys/models may share one pool. A process-wide counter registry survives every save and keeps outstanding leases across removal/re-addition. Occupancy is attached to stable account/credential identities; assigning or renaming a pool immediately includes existing requests, including formerly unlimited requests. Pool limits may shrink below occupancy, preventing further admission until occupancy falls below the new limit. Nonblocking acquisition precedes circuit admission. A full target is skipped immediately, then remaining targets of its layer, then lower layers. Local capacity skips never trip provider circuits. The lease lasts through same-target retries and the complete upstream stream, and is released on cancellation, failure or completion. Exhausted local capacity returns a retryable 503 rather than an unbounded queue. An independent concurrent save cannot reset occupied counters.

## API contract
GET /api/routing returns {revision,document,models,pools,pricing,now}. document is Config JSON with every api_key replaced by an empty string. Endpoints containing credentials, a query or a fragment are returned as null; leaving the endpoint blank preserves the existing endpoint for the same backend and adapter. models runtime rows contain name, aliases, active_schedule (null for default), effective_order (layer names), and layers [{index,name,strategy,targets:[{backend,credential,upstream_model,circuit,pool,in_flight,max_in_flight}]}]. pools holds live {id,in_flight,max_in_flight}. now is an RFC3339 timestamp. GET accepts ?at=RFC3339 for preview of committed routing and price rules without changing runtime. pricing contains backend/model identities, active_window and selected rates. PUT /api/routing accepts {revision,document}, and returns the same workspace shape on success. Errors return {error}; 409 means stale revision or temporary validation capacity, 422 invalid candidate, 503 persistence unavailable. Existing /api/routing/stats, /api/stats, /api/requests and /api/status serve the captured active runtime. GET /api/stats accepts window=1h|1d|1w|1m|all and returns window {id,from_ms,to_ms}; omission retains lifetime totals for existing clients. The UI explicitly requests 1d initially. Finite global totals use request-start and attempt-start timestamps in [from_ms,to_ms), with the same completed-minute boundaries as model statistics. Attempt prices are the recorded historical amounts. Indexed minute/hour attempt buckets are backfilled transactionally and resumably from the existing ledger before traffic starts; all-time totals remain unchanged. Time buckets retain 32 days, while lifetime tables remain durable.

Config uses version 4 and adds top-level capacity_pools: [{id,max_in_flight}], credentials[].pool: optional string, models[].timezone: string (UTC default), models[].schedules: [{name,days,start,end,order}]. Version 3 configuration automatically upgrades in memory, then persists after constructing a valid runtime. A private original-file backup supports operational downgrade. Read-only directories retain a working in-memory migration and an actionable workspace notice. Model names, aliases, order, prices, protocols, keys, startup settings and historical ledger records are preserved; no schedules or local limits are invented. Repeated startup is idempotent. `--check` never writes the file. Backends retain existing adapter, endpoint, credentials, models and pricing fields. Model layer targets retain backend/credential/model references.
